# 게임 주스 점검

주스는 효과의 양이 아니라 행동과 결과가 전달되는 완성도다. 부족한 표현은 보강하고, 과하거나 중복된 표현은 줄인다.

상용 게임의 완성도를 기준으로, 현재 게임의 의도와 인과관계가 즉시 이해되는지 평가한다. 장르, 아트 방향, 플레이 속도와 대상 플랫폼에 맞춰 판단한다. 새로운 콘텐츠나 기능보다 **로직은 이미 존재하지만 표현이 부족한 사건**을 먼저 찾는다.

## 범위와 근거

- 점검·검토 요청의 기본 결과물은 근거가 있는 진단과 개선 우선순위다. 실제 수정까지 요청받았다면 해당 범위의 구현과 검증을 진행한다. 이미 받은 수정 권한을 다시 묻지 않는다.
- 프로젝트 지침과 검증 문서를 먼저 확인해 실제 대상 앱, 실행 경로, 허용된 검증 범위를 파악한다. 참고용 웹이나 이전 빌드를 현재 게임으로 오인하지 않는다.
- 주요 입력 처리, 게임 상태 전이, 결과·보상 처리, UI·애니메이션·오디오 호출을 연결해서 읽는다. 함수나 에셋의 존재만으로 실제 구현·사용을 확정하지 않는다.
- 실행 가능한 대상이라면 범위 안의 대표 상호작용을 직접 재생하여 입력 직후부터 정착까지 관찰한다. 한 장의 정지 화면이나 효과 함수의 존재만으로 동작의 체감 품질을 판정하지 않는다. 소리·햅틱·실기기 반응은 직접 확인한 범위를 구분한다.
- 근거를 코드 위치, 호출 경로, 관찰한 화면·시퀀스로 남긴다. **효과가 호출되는지**와 **대상 플랫폼에서 지각되는지**를 별도로 판정한다. 실행할 수 없거나 해당 감각을 확인할 수 없으면 미확인으로 표시하고, 이를 정상 또는 미구현으로 단정하지 않는다.
- 프로젝트의 기존 검증 도구와 정리 규칙을 따른다. 점검 요청을 전체 캠페인 재생·해결, 패키징, 배포 권한으로 확대하지 않는다. 관련 대표 사례로 범위를 한정하고 실행하지 못한 검증은 명시한다.

### 시간 흐름 확인

핵심 행동과 사용자가 어색하다고 지목한 행동은 실제 조작 속도로 살핀다. 실시간 관찰이나 짧은 녹화·연속 캡처 중 가능한 방법으로 **입력 직후 → 효과가 가장 강한 순간 → 움직임·결과 → 정착**을 확인한다. 사건에 없는 단계를 억지로 만들거나 모든 게임에 같은 캡처 수·시간값을 요구하지 않는다.

- 첫 반응이 언제 보이는지, 준비 동작이 본동작에 묻히는지, 대상이 사라지거나 다른 화면으로 바뀌기 전에 결과를 읽을 수 있는지 확인한다.
- 효과가 코드에 있어도 동시 이동, 짧은 지속 시간, 작은 화면 크기, 가림·잘림, 다른 효과와의 중첩 때문에 보이지 않으면 **표현 부족**으로 기록한다. 값이나 타임라인만 읽고 체감 완료로 처리하지 않는다.
- 짧은 반복 입력과 중단·재시작에서 반응이 누락되거나 겹쳐 남는지 확인한다. 반복 플레이에서는 지연과 피로도도 함께 판단한다.
- 참고 구현이나 이전 버전은 의도를 파악하는 근거로 쓸 수 있지만, 현재 대상 앱에서 같은 체감이 재현되는지는 따로 확인한다.

## 사건과 경험의 흐름

먼저 핵심 플레이 루프와 중요한 사건을 파악한다. 공격·피격·사망·획득·레벨업·보스는 실제 게임에 있을 때만 다룬다. 퍼즐이라면 선택, 이동 시도, 유효/무효 행동, 연쇄, 목표 달성, 실패, 재시작 등의 실제 규칙을 중심으로 본다.

각 핵심 사건을 다음 흐름으로 추적한다.

**입력/발생 조건 → Anticipation(준비) → 행동 → 충돌/변화 → 결과 → Recovery/정착**

자동 사건은 입력 대신 발생 조건에서 시작한다. 없는 단계는 생략 이유를 적으며, 모든 사건에 준비 동작이나 지연을 강제로 넣지 않는다. 즉각 반응해야 하는 입력을 연출 때문에 늦추지 않는다.

각 단계에서 다음을 확인한다.

- 실제 로직의 확정 시점과 플레이어가 이를 인지하는 시점이 일치하는가?
- 입력 접수, 실행 가능 여부, 성공/실패, 자원·목표 변화가 서로 구분되는가?
- 다음 행동이 가능한 시점이 명확한가? 중간 입력·연타·중단·재시작으로 연출이 겹치거나 낡은 상태가 남는가?
- 빠진 연결 구간, 아무 정보도 주지 않는 대기, 결과를 가리는 효과가 있는가?

연출 강도는 게임플레이 중요도와 빈도에 비례시킨다.

| 등급 | 판단 기준 | 연출 방향 |
| --- | --- | --- |
| 일반 행동 | 자주 반복하는 조작과 작은 변화 | 짧고 국소적이며 즉시 읽히는 반응 |
| 중요한 행동 | 전략적 결과, 큰 피해, 중요한 획득·목표 달성 | 결과를 구별하는 강조와 제한적인 보조 효과 |
| 클라이맥스 | 단계 완료, 결정적 실패, 보스 격파 등 | 인지·여운·마침표·보상을 연결하는 짧은 시퀀스 |

중요한 시퀀스는 개별 효과 목록으로 끝내지 않는다. 예를 들어 보스가 실제로 있는 게임에서는 마지막 공격의 임팩트 → 사망 인지 → 짧은 여운 → Victory → 보상 표시 전체를 검토한다. 각 구간의 시작 조건, 중첩 여부, 입력 잠금·재개와 총 체감 길이를 제안한다. 반복 플레이에서는 카운트업 즉시 완료, 빠른 재시작 등 기존 흐름을 덜 방해하는 방법을 검토하되 모든 연출에 스킵 기능을 새로 만들도록 요구하지 않는다.

## 평가 항목

전체 점검에서는 아래 항목을 각각 평가한다. 특정 사건만 요청받았다면 관련 항목으로 제한한다. 미적용 항목은 게임 규칙이나 플랫폼에 따른 이유를 적는다. **미구현 자체는 결함이 아니다.**

| 항목 | 확인할 내용 |
| --- | --- |
| 입력 직후 피드백 | 시각·청각·햅틱의 반응 시점, 입력 접수와 실행 결과의 구별 |
| 움직임·수치 변화 | Tween/Lerp/Easing의 목적, 가감속·정착, 값 변경의 추적 가능성 |
| 동작 표현 | Anticipation, Squash & Stretch, Follow-through, Secondary Motion의 필요성과 일관성 |
| 충돌·전투 피드백 | Hit Stop, Hit Flash, Knockback, Screen Shake가 실제 판정·위력·방향을 전달하는지 |
| 시각 효과 | Particle, Trail, Impact, Afterimage의 역할, 시야·대상·판정 가림 |
| 상태 변화 | Damage Preview, Trailing Health Bar, Count-up 등 해당 규칙의 변화량·최종값 전달 |
| 카메라 | Zoom, Kick, 이동·추적이 중요한 대상을 돕는지, 조작·판독을 방해하는지 |
| 생명주기 | 등장·획득·레벨업·사망·퇴장의 시작과 완료가 인지되는지 |
| 전환·승패 | 화면 전환, 결과 화면, Victory/Game Over의 연결과 감정적 마침표 |
| 버튼 상태 | PC Hover, Press, Release, Disabled 및 키보드/컨트롤러 사용 시 Focus; 모바일에서는 Hover 제외 |
| 정보 위계 | 목표·현재 행동·변화·다음 행동의 가독성, 실제 화면 크기에서의 구별 |
| 등장·퇴장 타이밍 | UI와 오브젝트가 읽기 전에 사라지거나 조작 영역을 갑자기 가리는지 |
| 사운드 동기화 | 예고·실행·접촉·결과와 소리의 시점, 반복음 중첩과 강조 서열 |
| 모바일 햅틱 | 사건의 중요도와 빈도에 맞는지, 지원·설정 여부, 직접 확인 범위 |
| 반복 피로 | 빈번한 흔들림·섬광·잠금·대기·카운트업이 반복 플레이를 방해하는지 |
| 효과 간 간섭 | 같은 정보의 과도한 중복, 상충하는 시선 유도, 더 중요한 정보의 가림 |

각 항목의 결과에는 **현재 구현 여부 / 실제 체감 여부 / 문제점 / 개선 효과 / 구현 난이도 / 우선순위**를 포함한다. 구현 여부는 구현·부분 구현·미구현·미확인·미적용으로 구분한다. 체감 여부는 직접 관찰한 대상과 시점에 한해 확인·약함·방해·미확인 등으로 적는다. 난이도는 낮음·중간·높음과 주요 의존성으로 설명하며, 근거 없는 정밀 일정은 제시하지 않는다.

시청각·햅틱이 같은 사건을 보강하는 것은 유용할 수 있다. 같은 정보를 전달한다는 이유만으로 삭제하지 말고 실제 방해·중복 비용을 평가한다. 모든 사건에 동일한 흔들림, 파티클, 사운드, 줌을 적용하지 않는다. 원인이 불명확한 문제를 효과 추가로 덮지 않는다.

## 유지·통합·삭제 검토

점검 범위 안에서 중복된 연출과 코드, 미사용 기능, 역할이 겹치는 UI, 스타일이 다른 요소를 조사한다.

- **유지:** 독립적인 정보·기능·접근성 역할이나 의도적인 중요도 차이가 있다.
- **통합:** 같은 상태·행동을 여러 코드와 UI가 관리해 타이밍·스타일이 어긋난다. 공통 표현 규칙과 상태 소유자를 제안한다.
- **삭제:** 실제 사용되지 않거나 정보 가치 없이 방해·대기·중복 비용만 만든다.

검색 결과만으로 미사용을 확정하지 않는다. 직렬화된 씬·프리팹, 이벤트 연결, 동적 로딩, 플랫폼 분기와 생성기에서의 사용을 확인한다. 확인이 부족하면 삭제 후보로 표시한다. 유사한 외형만 보고 기능 상태를 합치지 않는다. 점검과 무관한 광범위한 리팩터링으로 확대하지 않는다.

## 결과물과 구현 검증

보고서는 다음 내용을 실제 근거에 맞게 구성한다.

1. 점검 대상·플랫폼·검증 범위와 체감 완성도를 가장 크게 떨어뜨리는 발견 사항.
2. 중요한 사건별 6단계 흐름, 일반/중요/클라이맥스 등급, 로직과 표현의 단절 지점.
3. 평가 항목별 현재 구현 여부·문제점·개선 효과·난이도·우선순위. 관련 사건과 근거를 연결하고 동일한 제안을 반복하지 않는다.
4. 유지·통합·삭제 제안과 판단 근거.
5. 아래 순서의 실행 우선순위. 각각 대상 사건, 구체적 변경, 기대 효과와 완료 판단 기준을 적는다.
   - **1. 즉시 수정하면 효과가 큰 것:** 원인·결과 인지를 막거나 핵심 행동의 체감을 훼손하는 문제.
   - **2. 적은 비용으로 개선 가능한 것:** 기존 표현을 활용한 타이밍·상태·일관성 개선.
   - **3. 나중에 다듬을 디테일:** 핵심 이해와 조작에 영향이 작은 미세 조정.

불필요한 효과는 추천 목록을 채우기 위해 넣지 않는다. 현재 잘 작동하는 부분은 유지로 판단한다. 자동 검사 결과와 실제 시각·청각·햅틱 관찰 결과를 별도로 보고한다. 핵심 사건을 실행해 보지 못했다면 체감 완성도에 대한 최종 판정을 보류한다.

구현까지 요청받았다면 기존 연출·상태 관리 구조를 재사용하고 관련 런타임 참조와 생성 경로를 함께 갱신한다. 바꾼 사건을 실제 대상 앱에서 재생해 판정과 표현의 일치, 빠른 반복 입력, 종료·재시작 후 잔여 효과, 반복 플레이의 길이를 집중 확인한다. 도구로 확인할 수 없었던 체감 품질은 검증 완료로 표현하지 않는다.
