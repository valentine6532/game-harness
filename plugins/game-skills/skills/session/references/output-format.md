# Session 출력 형식

근거가 있는 항목만 채우고, 없는 숫자·시간·파일명은 만들지 않는다. 한 화면에서 상태를 읽을 수 있게 다음 골격을 유지한다.

```text
{작품명 또는 프로젝트명} ({work/run 식별자}) {회차} ─────────────────────────
한 줄 정체: {무엇을 만들고 있으며 지금 어느 단계인지}   진척 {완료}/{전체 또는 ?/?}

{공정1} ━━ {공정2} ━━▶ {현재 공정} ━━ {다음 공정} ━━ {마지막 공정}

끝난 공정  {막대}  {완료}/{전체}
  [ OK ]  {번호}. {공정} ········· {완료 근거와 핵심 결과}
  [ RUN]  {번호}. {공정} ········· {시작 시각/현재 산출물/남은 일}
  [TODO]  {범위} ··············· {아직 시작하지 않은 일}

미결·주의  {막대}  {해결}/{전체}
  [STOP]  {핵심 진행을 막는 결정 또는 의존성}
  [WARN]  {진행 가능하지만 조용히 위험한 문제}
  [ OK ]  {최근 해결된 중요한 문제}

다음 작업
  1. {가장 먼저 할 일}   <- 권장
  2. {병렬 또는 대안 작업}
  3. {정리·위험 제거 작업}
──────────────────────────────────────────────────────────

핵심만 짚으면

- 지금은 **{현재 문턱}**에 있다. {완료 범위와 아직 못 넘어간 이유}
- 직전에 끝난 건 **{최근 완료}**다. {commit/파일/검증 근거}
- 중요한 규칙 하나: **{이후 작업이 지켜야 할 도메인 규칙}**
- 실제로 막고 있는 것: {STOP 항목 또는 없음}
- 조용히 위험한 것: {WARN 항목 또는 없음}

{사용자가 결정할 짧은 질문. 결정이 필요 없으면 다음 권장 행동을 한 문장으로 끝낸다.}

자세히 보려면: {실제로 존재하는 상대경로 2~5개}
```

## 표시 규칙

- 공정 막대는 전체 공정 수를 시각적으로만 보조한다. 숫자와 모순되면 막대를 생략한다.
- 현재 공정 앞에 `▶`를 둔다. 병렬 공정이면 둘을 `RUN`으로 표시하고 흐름 줄에는 가장 중요한 gate를 가리킨다.
- 파일 경로는 repository root 기준 상대경로로 쓴다.
- `자세히 보려면`은 최신 일일 로그, 활성 회차 `progress.md`, 핵심 산출물 순서로 최대 5개를 쓴다.
- 커밋은 짧은 hash와 제목을 함께 쓴다.
- 근거 없는 시간, 퍼센트, 완료 판정은 쓰지 않는다.
- `STOP`과 `WARN`을 구분한다. 다음 핵심 공정을 실제로 막지 않으면 `WARN`이다.
