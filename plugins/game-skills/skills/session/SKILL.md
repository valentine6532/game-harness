# Session

현재 작업 디렉터리의 프로젝트 상태를 추측하지 말고 증거로 복원한다.

## 실행

1. `git rev-parse --show-toplevel`로 repository root를 찾는다. Git 저장소가 아니면 현재 작업 디렉터리를 root로 사용한다.
2. 이 `SKILL.md`와 같은 skill 디렉터리의 `scripts/collect_session.py`를 찾아 다음 의미로 실행한다.

   ```text
   python <session-skill-dir>/scripts/collect_session.py --root <repository-root>
   ```

   `python`이 없으면 `python3`, Windows에서는 `py -3`을 시도한다. 모두 없으면 Git 상태와 아래 문서를 읽기 전용 명령으로 직접 수집한다.
3. repository root에 `harness/skills/session/SKILL.md`가 있으면 끝까지 읽고 프로젝트 고유 규칙을 추가 적용한다. 전역 규칙과 충돌하면 프로젝트 규칙을 우선한다.
4. 수집기가 제시한 활성 `progress.md`, 최신 `logs/YYYY-MM-DD.md`, 작업 인덱스와 핵심 산출물만 추가로 읽는다.

## 활성 범위 선택

사용자가 작품·회차를 지정하면 해당 범위를 우선한다. 지정하지 않았으면 다음 순서로 찾는다.

1. 최근 수정된 `progress.md`의 활성 범위
2. 최신 일일 로그의 `RUN`, `STOP`, `다음` 항목
3. `works/*/EPISODES.md`나 작업 목록의 미완료 항목
4. Git의 최근 커밋과 working tree 변경

후보가 여러 개면 프로젝트 전체를 먼저 요약하고 후보별 상태를 나눈다. 근거 없이 하나를 선택하지 않는다.

## 증거 우선순위

서로 어긋나면 다음 순서로 판단하고 불일치를 `[WARN]` 또는 `[STOP]`으로 표시한다.

1. 실제 파일·테스트·Git 상태
2. 활성 `progress.md`와 실제 산출물
3. 프로젝트 인덱스, 작업 목록, `EPISODES.md`
4. 최신 `logs/YYYY-MM-DD.md`
5. 이전 로그와 대화 기억

로그는 이력이지 현재 상태의 단일 진실 공급원이 아니다. 완료라고 기록됐어도 필수 산출물이 없으면 완료로 세지 않는다.

## 상태 판정

- `[ OK ]`: 필수 산출물이나 명시적 검증 근거가 있다.
- `[ RUN]`: 시작 근거와 미완료 항목이 함께 있다.
- `[TODO]`: 예정됐지만 시작 근거가 없다.
- `[STOP]`: 결정, 누락 의존성, 손실 위험이 다음 핵심 공정을 막는다.
- `[WARN]`: 진행은 가능하지만 문서 불일치, 미추적 파일, 검증 누락 같은 위험이 있다.

공정표가 있을 때만 완료 수를 계산한다. 근거가 부족하면 `?/?`로 표시하고 숫자를 만들지 않는다.

## 출력

`references/output-format.md`를 읽고 다음을 한 화면에 제시한다.

- 제목, 한 줄 정체, 진척도
- 전체 공정 흐름과 현재 위치
- 완료·진행·예정 공정
- 미결·주의 사항
- 우선순위 다음 작업 2~4개와 권장안 하나
- 핵심 해설 3~5개
- 실제 근거 경로

`자세히 보려면`에는 존재하는 경우 최신 일일 로그, 활성 `progress.md`, 핵심 산출물 순서로 최대 5개를 쓴다. 사용자의 결정이 필요할 때만 마지막에 질문 하나를 둔다.

## 기록

단순 `$session` 조회는 파일을 수정하지 않는다. 사용자가 `$session 기록`, `세션 상태를 로그로 남겨`처럼 명시했을 때만 `references/logging-protocol.md` 형식으로 root의 `logs/YYYY-MM-DD.md`에 append한다.

실제 작업을 수행한 다른 세션에서는 의미 있는 완료, 중단, 결정, 위험, handoff가 생길 때 같은 로그 규약을 적용한다.

## 실패 처리

- `logs/`가 없으면 `[WARN] 작업 로그 없음`으로 표시하고 다른 증거로 계속한다.
- 진행 문서와 실제 파일이 어긋나면 자동 수정하지 말고 불일치와 수정 권장 위치를 제시한다.
- 근거가 거의 없으면 알려진 사실과 불명확한 부분을 분리하고 진행 문서 생성을 첫 다음 작업으로 둔다.
