# Unity 프로젝트에서

프로젝트에 자체 검증 절차와 에이전트 지침이 있으면 그것이 우선이다. 아래는 그런 것이 없을 때의 기본값과, 있어도 알아 둘 Unity의 특성이다.

## 설정을 한 곳에서 관리

제품명과 버전이 설정 코드, 빌드 검사, 문서에 흩어져 있으면 서로 달라진다. 에디터 코드에 상수 하나를 두고 모든 설정·검사 코드가 그것을 참조하게 한다. 방침 주소도 런타임 상수 하나로 둔다.

프로젝트 설정 파일(YAML)을 손으로 고치지 말고 에디터 API로 적용하고 같은 코드에서 값을 검사한다. 에디터가 열려 있으면 손으로 고친 값을 에디터가 덮어쓸 수 있다.

## iOS 빌드 후처리

Info.plist에 넣을 키는 빌드 후처리로 기록한다.

| 키 | 값 | 이유 |
|---|---|---|
| `ITSAppUsesNonExemptEncryption` | false | 수출 규정 질문이 빌드마다 뜨지 않게. 자체 암호화가 없을 때만 |
| `GOOGLE_ANALYTICS_DEFAULT_ALLOW_AD_PERSONALIZATION_SIGNALS` | false | 어린이 대상 앱. 앱 시작 직후 구간까지 막음 |
| `GOOGLE_ANALYTICS_IDFV_COLLECTION_ENABLED` | false | 통계가 기기 식별자를 모으지 않게 |

- Xcode 프로젝트 API(`UnityEditor.iOS.Xcode`)를 쓰는 코드는 `#if UNITY_IOS`로 감싼다. iOS 모듈이 없는 환경에서 컴파일이 깨지지 않게 하기 위해서다.
- 감싼 코드는 에디터의 현재 빌드 대상이 Android면 컴파일되지 않아 로컬에서 확인할 수 없다. Unity에 들어 있는 컴파일러로 `UNITY_IOS`를 정의해 그 파일만 컴파일해 보고, 실제 동작은 다음 빌드 로그의 표식으로 확인한다. 사용자에게 "Windows에서는 컴파일까지만 확인했다"고 말한다.
- 광고·Firebase 플러그인이 먼저 자기 키를 쓰도록 후처리 순서를 뒤로 둔다.

## 에디터의 한계

| 에디터에서 보이는 것 | 실제 기기 |
|---|---|
| 상품 가격이 "준비 중" | 스토어 가격 |
| `Application.platform`이 에디터 | iPhone 또는 Android. 기기 시뮬레이터가 흉내 내는 플랫폼은 `UnityEngine.Device.Application.platform`으로 읽는다 |
| 지역 동의 화면 버튼이 항상 보임 | 필요한 지역에서만 |
| 광고는 시험용 화면 | 실제 광고 |

사용자가 에디터에서 본 것을 실제 동작으로 오해하지 않게 미리 말한다.

## 검증을 돌릴 때

- 에디터가 그 프로젝트를 열고 있으면 창 없는 실행(batchmode)은 실패한다. `Temp/UnityLockfile`과 프로세스 명령줄로 확인한다.
- 열려 있는 에디터에 작업을 요청하는 방식을 쓰는 프로젝트라면, 에디터 창이 앞에 있고 플레이 모드가 아닐 때만 요청을 가져간다. 몇 분 안에 안 가져가면 사용자에게 창을 앞에 두거나 닫아 달라고 한다.
- 새로 쓴 에디터 스크립트는 에디터가 다시 컴파일한 뒤에야 요청을 처리한다. 가져오기 요청을 먼저 보낸다.
- 화면 캡처를 자동으로 찍을 때 시작 로고(스플래시)가 끝났는지 기다린다. 자동 검사는 통과했는데 캡처에는 로고만 찍히는 일이 있다. **저장된 캡처를 직접 열어 보기 전에는 화면을 확인했다고 말하지 않는다.**
- 검증이 끝난 뒤 생긴 임시 캡처와 상세 로그는 지우고 요약만 남긴다.

## 스크린샷을 화면에서 직접 그리기

기존 검증용 화면 구성(임시 저장 기록으로 특정 화면을 띄우는 훅)이 있으면 그것으로 스토어 스크린샷을 그린다. 실제 저장 기록은 건드리지 않는다.

- 콘솔이 받는 픽셀 크기를 먼저 확인하고, 그 크기가 나오는 논리 해상도와 배율로 그린다. 예: 393×852 논리 크기에 3배 = 1179×2556.
- 투명도 없이 저장한다(RGB).
- 개발용 버튼, 에디터 전용 표시, 결제·보호자 화면이 찍히지 않게 한다.
- 화면 속 글이 틀리면 스크린샷이 아니라 앱을 고친다.

## 글자가 이미지에 구워져 있을 때

화면에 보이는 문구가 코드와 번역 목록에서 검색되지 않으면, 다른 원본(웹 버전 등)에서 구워 낸 이미지일 수 있다.

- 레이아웃 데이터에서 그 부분이 어떤 그림을 참조하는지 찾는다.
- 전체 내보내기 도구는 다른 그림 수십 장과 정리 단계를 끌고 올 수 있다. 해당 이미지 한 장만 다시 만들고, 텍스처 묶음을 다시 만든 뒤 **바뀐 파일이 예상한 것뿐인지** 확인한다. 범위가 넓어지면 되돌리고 알린다.
- 이미지로 된 글은 언어를 바꿔도 그대로다. 다른 언어권에 출시할 때 문제가 된다고 알린다.

## 빌드

- 클라우드 빌드는 푸시된 커밋으로 만들어진다. 사용자가 빌드를 누르기 전에 커밋·푸시가 끝났는지, 빌드가 잡은 커밋이 맞는지 확인한다.
- 에이전트가 클라우드 빌드를 실행하려면 별도 인증이 필요하다. 없으면 없다고 말하고, 자동 빌드 설정이나 서비스 계정 키라는 선택지를 설명한다.
- 프로젝트에 "명시적으로 요청받기 전에는 패키징하지 않는다" 같은 규칙이 있으면 지킨다. 빌드와 스토어 업로드는 별개의 허락이다.
- 에디터가 의도하지 않은 설정 파일을 바꿔 놓는 일이 있다(예: 품질 설정의 플랫폼별 기본값이 비워짐). 커밋 전에 설정 파일의 변경을 읽어 보고, 의도하지 않은 것은 빼고 사용자에게 묻는다.
