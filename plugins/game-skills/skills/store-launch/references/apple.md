# Apple: App Store Connect와 TestFlight

메뉴 이름은 2026-10 기준이다. 화면과 다르면 화면을 따른다. 사용자가 화면 글을 붙여 넣으면 이 문서의 표로 칸을 분류해 준다.

## 1. 전체 순서

| 순서 | 위치 | 할 일 | 빌드 필요 |
|---|---|---|---|
| 1 | 비즈니스 | 유료 앱 계약이 "활성"인지. 아니면 계좌·세금 입력. 검토에 며칠 걸릴 수 있어 가장 먼저 | 아니요 |
| 2 | 앱 정보 | 부제, 카테고리, 콘텐츠 권한, 연령 등급 | 아니요 |
| 3 | 앱이 수집하는 개인정보 | 방침 주소, 수집 데이터 신고 | 아니요 |
| 4 | 가격 및 사용 가능 여부 | 가격, 국가 | 아니요 |
| 5 | 수익화 > 앱 내 구입 | 상품별 가격·이름·설명·심사용 스크린샷 | 스크린샷에 필요 |
| 6 | 버전 페이지 | 스크린샷, 설명, 키워드, 지원 URL, 버전, 저작권, 심사 정보, 출시 방식 | 아니요 |
| 7 | 버전 페이지 | 빌드와 상품을 추가하고 "심사에 추가" | 예 |

빌드가 도는 동안 1~6을 진행하면 시간이 절약된다.

버전 페이지 찾기: 앱 > **배포** 탭(예전 이름 App Store) > 왼쪽 **iOS 앱** 아래의 `1.0 제출 준비 중`. 앱을 등록할 때 하나가 자동으로 만들어진다. 없으면 `+`로 만든다. TestFlight 탭에서는 보이지 않는다.

## 2. 버전 페이지 칸별 분류

| 칸 | 분류 | 메모 |
|---|---|---|
| 앱 미리보기 및 스크린샷 | 필수 | 7번 참고 |
| 설명 | 필수 | 4,000자 이내 |
| 키워드 | 필수 | 100자 이내, 쉼표로 구분, 띄어쓰기 없이. 앱 이름에 든 단어는 다시 넣지 않아도 검색됨 |
| 지원 URL | 필수 | 문의 페이지. 없으면 `assets/site/`의 지원 페이지 틀로 만든다 |
| 버전 | 필수 | 빌드의 버전과 같아야 빌드를 고를 수 있다. 자동 생성된 `1.0`을 실제 값으로 고친다 |
| 저작권 | 필수 | `연도 이름` 형식 |
| 빌드 | 필수 | TestFlight에 올라온 빌드 선택 |
| 앱 심사 정보 > 연락처 | 필수 | 심사관만 봄 |
| 출시 방식 | 필수 | "수동으로 버전 출시" 추천. 승인 즉시 공개되지 않고, 법적 신고 같은 남은 일을 끝낸 뒤 직접 출시할 수 있다 |
| 앱 심사 정보 > 메모 | 하면 좋음 | 영어로. 로그인이 없다는 점, 보호자 확인 통과 방법, 결제 위치, 광고가 언제 나오는지 |
| 프로모션 텍스트 | 하면 좋음 | 170자. 심사 없이 바꿀 수 있음 |
| 로그인 정보 | 해당 시 | 로그인 기능이 없으면 "로그인 필요" 체크를 해제 |
| 헤더, 마케팅 URL, 첨부 파일 | 안 해도 됨 | |
| 라우팅 앱 적용 범위 파일 | 안 해도 됨 | 지도·길찾기 앱 전용 |
| 앱 클립, iMessage 앱, Game Center | 안 해도 됨 | 해당 기능이 없으면 |

## 3. 앱 정보

| 칸 | 메모 |
|---|---|
| 이름 | 30자 이내 |
| 부제 | 30자 이내. 이름 아래에 보임 |
| 카테고리 | 기본과 보조. 게임은 하위 카테고리 두 개까지 |
| 콘텐츠 권한 | 남의 저작물을 싣지 않으면 "없음" |
| 연령 등급 | 설문. 폭력 등 콘텐츠 항목, 광고 포함 여부, 채팅·사용자 제작 콘텐츠, 확률형 아이템 |
| 어린이용으로 제작됨 | Kids Category. `decisions.md` 참고 |

페이지 아래쪽의 부가 항목은 대부분 해당 없음이다.

| 항목 | 언제 필요한가 |
|---|---|
| 앱 암호화 문서 업로드 | 자체 암호화를 쓰는 앱만 |
| 디지털 서비스법 | EU에 판매할 때. 제출 시 막으면 그때 설정 |
| 베트남 게임 허가권 | 베트남 출시 시 |
| 규제 대상 의료 기기 | 의료·건강 앱 |
| App Store 서버 알림 | 구매·환불 소식을 받을 자체 서버가 있을 때 |
| 앱 공유 암호 | 자동 갱신 구독 상품이 있을 때 |
| 앱 삭제 | 누르지 않는다 |

## 4. 앱이 수집하는 개인정보

위치: 배포 탭 왼쪽 메뉴의 "앱이 수집하는 개인정보"(App Privacy).

1. 위쪽에서 개인정보 처리방침 URL을 넣는다.
2. 데이터 유형 "시작하기" > "데이터를 수집합니까?" 질문. **앱에 들어 있는 SDK가 모으는 것까지 포함해 답한다.** 운영자가 직접 모으는 것이 없어도 광고·통계 SDK가 있으면 "예"다.
3. 데이터 유형을 체크한다. 답안은 `privacy.md`의 절차로 만든다.
4. 유형마다 용도 창이 뜬다. 선택지: 타사 광고, 개발자의 광고 또는 마케팅, 분석, 제품 개인 맞춤화, 앱 기능, 기타 목적.
5. 유형마다 "사용자의 신원에 연결됩니까?", "추적 목적으로 사용합니까?"를 묻는다.
6. 오른쪽 위 **게시**를 눌러야 저장된다.

## 5. 가격 및 사용 가능 여부

가격, 국가, 사전 주문. "Apple Silicon Mac에서 사용 가능"과 "Apple Vision Pro에서 사용 가능"은 시험해 본 적이 없으면 해제한다.

## 6. 앱 내 구입 상품

위치: 수익화 > 앱 내 구입. 상품마다 상태가 "제출 준비 완료"가 되어야 심사에 낼 수 있다.

| 칸 | 넣을 것 |
|---|---|
| 판매 가능 여부 | 판매 국가 |
| 가격 일정 | 기준 국가와 가격 |
| 현지화 | 언어별 표시 이름과 설명. 출시 국가 언어만 있어도 됨 |
| 심사 정보 > 스크린샷 | 앱에서 그 상품이 보이는 화면. 여러 상품에 같은 이미지를 써도 됨 |
| 심사 정보 > 메모 | 상품을 어디서 살 수 있는지 한 줄 |

- 상품 유형과 상품 ID는 만든 뒤 바꿀 수 없다. 앱 코드의 ID와 글자 하나까지 같아야 한다.
- 가족 공유는 켜면 다시 끌 수 없다.
- 첫 상품은 앱 버전과 함께 심사받는다. 버전 페이지의 "앱 내 구입 및 구독" 칸에 추가한다. 이 칸은 "제출 준비 완료" 상품이 있어야 보인다.
- 유료 앱 계약이 활성 상태가 아니면 앱에서 상품을 불러오지 못한다.

## 7. 스크린샷

- **만들기 전에 업로드 칸 아래에 적힌 허용 크기를 사용자에게 확인받는다.** 2026-10에 필수 칸은 "Dynamic Island 지원 iPhone (중형 디스플레이)"였고 세로 1179×2556 또는 1206×2622만 받았다. 1290×2796은 거부됐다. 이 값도 바뀔 수 있다.
- 투명도(알파)가 있는 PNG는 거부된다. RGB로 저장한다.
- 1~10장. 검색 결과에는 앞의 3장이 보이므로 핵심 화면을 앞에 둔다. 결제나 보호자 메뉴 화면은 홍보용에 넣지 않는다.
- iPhone 전용 앱이면 iPad 스크린샷은 필요 없다.
- `scripts/fit_screenshot.py --check 폴더 --size 1179x2556`로 검사하고, `--convert`로 크기와 투명도를 맞춘다. 가능하면 처음부터 그 크기로 화면을 그려 찍는 편이 선명하다.
- 실제 앱 화면이어야 한다. 화면 속 문구가 틀리면 스크린샷이 아니라 앱을 고친다.

## 8. TestFlight와 빌드

- TestFlight로 설치한 빌드의 결제는 자동으로 시험 환경으로 연결되어 청구되지 않는다. 구매·복원 흐름은 실제와 같다.
- 한 번 산 비소모품은 그 Apple 계정에 구매한 것으로 남는다. 구매 과정을 처음부터 다시 보려면 다른 테스터 계정이 필요할 수 있다.
- 빌드 옆에 수출 규정 문서 누락 표시가 뜨면 "앱 암호화 문서" 질문이 나온다. 자체 암호화 없이 운영체제의 HTTPS만 쓰는 앱은 "위에 언급된 알고리즘에 모두 해당하지 않음"이다. Info.plist에 `ITSAppUsesNonExemptEncryption=false`를 넣으면 빌드마다 묻지 않는다.
- TestFlight 목록에서 버전 번호를 확인한다. 예전 버전 아래의 빌드를 새 빌드로 착각하기 쉽다.

## 9. 실기기 확인표

| 확인할 것 | 기대 결과 |
|---|---|
| 상품 화면 | 스토어 가격이 표시됨. 안 뜨면 유료 앱 계약, 상품 ID, 상품 정보 순으로 확인 |
| 구매 | 시험 환경 표시가 있는 결제 창, 구매 후 혜택 적용 |
| 앱 삭제 → 재설치 → 구매 복원 | 혜택이 돌아옴 |
| 광고 | 재생되고 끝까지 보면 보상 지급 |
| 방침 링크 | 브라우저로 열림 |
| 언어 전환 | 글자가 잘리거나 깨지지 않음 |
| 결제 안내 문구 | 다른 스토어 이름이 보이지 않음 |

## 10. 자주 반려되는 사유

- 앱이나 스토어 문구에 다른 플랫폼 이름이 나옴.
- Kids Category가 아닌데 "어린이용" 표현을 씀, 또는 Kids Category인데 외부 광고·분석이 들어 있음.
- 구매 복원 버튼이 없음.
- 개인정보 신고가 실제 수집과 다름, 방침 링크가 앱 안에 없음.
- 심사관이 결제 화면에 도달하지 못함. 심사 메모에 경로를 적는다.
- 스크린샷이 실제 앱과 다름.

지침 번호와 문구는 제출 전에 최신 심사 지침으로 확인한다.
