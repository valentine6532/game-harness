# 작업 순서

게임을 바꾸는 작업은 계획, 실행, 검증, 보고 순서로 진행한다.

## 1. 계획

- `.game-harness/project.yaml`에서 작업 대상 폴더, 데이터 원본 위치, 검증 실행 방법, 요청 없이는 하지 않는 작업을 확인한다.
- `.game-harness/overrides/`에 이번 작업과 관련된 예외가 있는지 확인한다.
- 사용자가 바꾸라고 한 대상이 어느 것인지 확인한다. 참고용 버전이나 생성된 파일을 대상으로 착각하지 않는다.
- 요청받은 범위 안에서 작업한다. 도구나 스킬을 설치하라는 요청은 게임 전체를 다시 쓰라는 요청이 아니다.

## 2. 실행

- 원본을 고친다. 원본에서 만들어지는 파일(변환된 데이터, 묶음 파일, 생성된 이미지)을 직접 고치지 않는다. 원본을 고친 뒤 프로젝트가 정한 동기화 명령을 실행한다.
- 무언가를 옮기거나 바꿀 때는 그것을 참조하는 코드와 생성 도구도 함께 고친다.
- `project.yaml`의 "요청 없이는 하지 않는 작업"은 사용자가 그 작업을 명시적으로 요청했을 때만 한다. "계속해줘", "확인해줘" 같은 요청은 허락이 아니다.

## 3. 검증

`verification.md`를 따른다.

## 4. 보고

- 무엇을 바꿨는지, 어떤 검사를 실제로 돌렸는지, 눈으로 무엇을 확인했는지 나눠서 말한다.
- 돌리지 않은 검사와 하지 못한 일은 그렇다고 말한다.
- 하네스 절차 자체에 문제가 있으면 `harness/` 안을 고치지 않는다. 당장은 `overrides/`에 임시 규칙을 적고, 공통 하네스에 반영할지 사용자에게 알린다.
