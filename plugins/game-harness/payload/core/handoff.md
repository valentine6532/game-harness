# 작업 인계

여러 세션(Claude, Codex, 다른 PC)이 같은 프로젝트에서 일할 때, 서로 무엇을 하고 있는지 알고 멈춘 작업을 정확히 이어받기 위한 기록이다.

## 구조

```text
.game-harness/work/
├─ now/                  아직 끝나지 않은 작업. 작업 하나에 파일 하나
│  ├─ 1005-1420-lobby-ui.md
│  └─ 1005-1435-stage-data.md
└─ done/
   └─ 2026-10/
      └─ 04/             끝난 작업을 끝난 날짜별로 옮겨 둔 보관함
         └─ 1004-2210-sound.md
```

- 파일 하나는 작업 하나다. 그 작업을 잡은 세션만 그 파일을 고친다. 여러 세션이 함께 고치는 파일은 없다.
- 파일 이름은 작업 ID다. `<월일>-<시작 시각>-<짧은 영문 이름>.md` 형식으로 짓는다. 날짜와 시각은 사용자의 현지 시간이다.

## 언제 무엇을 하는가

### 작업을 시작하기 전

파일을 고치거나 만들거나, 검증·조사·진단을 하는 작업이 대상이다. 파일을 건드리지 않는 질문과 답은 대상이 아니다.

1. `now/` 폴더의 파일을 모두 읽는다.
2. 사용자의 요청이 `now/`에 있는 멈춘 작업을 이어가는 것이면, 그 파일을 넘겨받는다. `담당`을 자신으로 바꾸고 `다음 재개 지점`부터 시작한다.
3. 새 작업이면 아래 "겹침 판단"을 한다.
4. 겹치지 않으면 아래 "작업 파일을 만드는 기준"에 따라 `now/`에 자신의 작업 파일을 만든 뒤 작업을 시작한다.

#### 작업 파일을 만드는 기준

시작하기 전에 아래 세 가지를 확인한다. **하나라도 해당하면 파일을 만든다.**

- 파일을 둘 이상 고치거나 만든다.
- 함께 쓰는 것을 오래 차지한다. 기기 빌드, 전체 검증, 생성 자원을 지우고 다시 만드는 작업이 그렇다. 고친 것을 확인하려고 에디터나 검증을 잠깐 쓰는 것은 여기에 들지 않는다.
- 이번 답변 안에서 끝나지 않을 수 있다. 여러 단계로 이어지거나, 사용자의 확인이나 입력을 기다려야 하는 경우다.

셋 다 해당하지 않으면, 곧 파일 하나만 고치고(확인을 위한 짧은 검증 포함) 이번 답변 안에서 끝나는 작업이면 파일을 만들지 않는다. 이때도 1~3번의 읽기와 겹침 판단은 한다.

파일 없이 시작했는데 하다 보니 위 기준에 해당하게 되면, 그 시점에 파일을 만든다. 어느 쪽인지 애매하면 만든다.

사용자가 "어디까지 했어?", "마지막 작업이 뭐야?", "이어서 해줘"라고 하면 답하기 전에 `now/`를 읽는다. `now/`가 비어 있으면 `done/`에서 가장 최근 날짜 폴더의 파일을 읽어 답한다.

### 작업 중

`다음 재개 지점`이 바뀌었을 때만 자신의 파일을 고친다. 재개 지점, 남은 일, 마지막 갱신 시각을 고치고 `기록`에 한 줄을 덧붙인다. 명령 하나하나를 적지 않는다.

작업하다가 처음 적은 것보다 넓은 곳을 건드리게 되면, 건드리기 전에 `now/`를 다시 읽어 겹침을 확인하고 자신의 `건드리는 곳`을 고친다.

### 작업을 멈출 때

사용자가 다른 일을 시키거나, 필요한 입력이 없어 진행할 수 없으면 `상태`를 `멈춤` 또는 `막힘`으로 바꾸고 재개 지점과 이유를 적는다. 파일은 `now/`에 둔다.

### 작업이 끝났을 때

1. `상태`를 `끝남`으로 바꾸고 완료 내용, 검증 결과, 커밋 번호를 적는다.
2. 파일을 `done/<연-월>/<일>/`로 옮긴다. 예: `done/2026-10/05/`. 폴더는 작업이 끝난 날짜다. 파일 이름은 바꾸지 않는다.
3. 작업을 커밋할 때 이 파일 이동도 같은 커밋에 넣는다. 기록만 담은 커밋을 따로 만들지 않는다.

작업 파일을 만든 작업은 끝나면 항상 `done/`으로 옮긴다. 남길지 말지를 끝날 때 다시 판단하지 않는다. 파일을 만들지 않은 작업은 `done/`에도 남기지 않으며, 그 기록은 git 커밋이다.

## 겹침 판단

자신이 하려는 일과 `now/`에 있는 다른 작업의 `건드리는 곳`을 비교한다. `상태`가 `멈춤`이나 `막힘`인 작업도 비교 대상이다.

다음 중 하나라도 해당하면 겹친다.

- 같은 파일을 고친다.
- 한쪽이 적은 폴더 안에 다른 쪽의 파일이나 폴더가 있다.
- 한쪽이 고치는 원본에서 다른 쪽이 쓰는 생성 파일이 만들어진다. 예: 데이터 원본과 그 원본에서 변환된 데이터.
- 다른 작업이 함께 쓰는 것을 오래 차지하고 있고, 자신도 그것이 필요하다. 기기 빌드, 전체 검증, 생성 자원을 지우고 다시 만드는 작업이 그렇다. 이런 작업은 `건드리는 곳`에 폴더와 함께 이름으로 적는다.

고친 것을 확인하려고 에디터나 검증을 잠깐 쓰는 것은 겹침이 아니다. 대부분의 작업이 그렇게 하므로, 이것을 겹침으로 보면 아무도 함께 일할 수 없다. 이 경우는 아래 "함께 쓰는 것의 차례"를 따른다.

겹치면 진행하지 않는다. 어느 작업과 어디가 겹치는지 사용자에게 알리고, 기다릴지, 겹치지 않는 부분만 먼저 할지, 그래도 진행할지 묻는다.

아직 어디를 건드릴지 모르면 예상되는 범위를 넓게 적고 시작한 뒤, 범위가 정해지면 좁힌다. 넓게 적은 동안에는 다른 세션이 그 범위를 피한다.

이 판단은 잠금 장치가 아니라 적힌 내용을 읽고 하는 판단이다. `건드리는 곳`을 정확히 적어야 다른 세션이 제대로 판단할 수 있다.

## 함께 쓰는 것의 차례

엔진 에디터, 검증 실행, 데이터 동기화처럼 한 번에 한 세션만 쓸 수 있는 것은, 작업 영역이 달라도 쓰는 순간에는 차례를 지켜야 한다.

프로젝트에 작업 대기열이 있으면 그것을 쓴다. `project.yaml`의 검증 실행 방법이 요청을 줄 세워 처리한다면 그 방법대로 요청을 넣으면 되고, 아래 절차는 필요 없다.

대기열이 없으면 다음과 같이 한다.

1. 쓰기 직전에 `now/`를 다시 읽는다.
2. 다른 작업 파일의 `사용 중`에 같은 것이 적혀 있으면 쓰지 않는다. 그 작업이 끝내기를 기다렸다가 다시 확인하거나, 사용자에게 알린다.
3. 비어 있으면 자신의 작업 파일 `사용 중`에 적고 쓴다. 작업 파일이 없는 작은 작업이면 이때 만든다.
4. 다 쓰면 바로 `사용 중`을 `없음`으로 되돌린다.

### 다른 세션의 수정이 섞인 검증

같은 폴더에서 일하는 세션들은 파일을 공유한다. 검증을 돌리면 다른 세션이 고치는 중인 내용도 함께 들어간다. 그래서 다음을 지킨다.

- 검증이 실패하면, 실패한 곳이 다른 `진행 중` 작업의 `건드리는 곳`에 속하는지 먼저 본다. 속하면 자신이 고치지 않는다. 그 작업 때문일 수 있다고 사용자에게 알린다.
- 검증 결과를 보고할 때 다른 세션의 진행 중인 수정이 섞인 상태였다면 그렇다고 적는다.
- 서로의 수정이 섞이지 않은 검증이 필요하면, 다른 작업이 끝나거나 멈춘 뒤에 다시 돌린다.

### 오래된 "진행 중"

`진행 중`인데 `마지막 갱신`이 오래됐다면 그 세션이 기록 없이 끝났을 수 있다. 짐작으로 넘겨받거나 무시하지 않는다. 사용자에게 그 작업이 아직 진행 중인지 묻는다.

## 파일 형식

```markdown
# 로비 버튼 간격 수정

- 작업 ID: 1005-1420-lobby-ui
- 상태: 진행 중
- 담당: claude (2026-10-05 14:20 시작)
- 마지막 갱신: 2026-10-05 14:55
- 요청: 로비 화면 버튼 간격이 좁다. 넓혀 달라.
- 건드리는 곳: client/Assets/UI/Lobby/
- 사용 중: 없음
- 다음 재개 지점: 간격 수정은 끝났다. 에디터에서 화면을 눈으로 확인하는 것부터 한다.
- 남은 일: 화면 확인, 커밋
- 주의사항: 상점 버튼은 다른 프리팹을 공유하므로 건드리지 않았다.

## 기록

- 14:20 시작. 간격 값이 LobbyLayout 프리팹에 있는 것을 확인.
- 14:55 간격 수정 완료. 컴파일 확인.
```

`사용 중`에는 지금 이 순간 쓰고 있는 것(예: `Unity 에디터`)만 적고, 다 쓰면 `없음`으로 되돌린다. `상태`는 `진행 중`, `멈춤`, `막힘`, `끝남` 중 하나다. 끝난 파일에는 아래 항목을 더한다.

```markdown
- 완료 내용: 버튼 간격 12에서 20으로 수정.
- 검증: 컴파일 통과. 에디터에서 로비 화면을 눈으로 확인.
- 커밋: a1b2c3d
```

## 적지 않는 것

- 비밀값, 인증 정보, 개인정보
- 긴 원문이나 도구 출력 전체
- 명령 하나하나의 실행 내역
- 커밋 기록을 그대로 옮긴 변경 목록. 변경 이력의 기준은 git이다.

## 기록과 실제가 다를 때

실제 파일과 git 상태를 우선한다. 차이를 자신의 작업 파일 `기록`에 적는다. 다른 세션의 파일은 고치지 않는다.
