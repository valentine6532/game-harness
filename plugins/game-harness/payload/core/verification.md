# 검증

## 범위

- 바꾼 것을 확인하는 데 필요한 검사는 따로 허락을 구하지 않고 돌린다. 영향받는 화면이나 스테이지의 실행, 대표 사례, 보상과 저장·불러오기 확인, 화면 점검, 컴파일, 자원과 데이터 점검이 여기에 든다.
- 공통 내부 로직은 작은 규칙 단위 시험과 대표 사례로 확인한다.
- 전체를 훑는 검사(모든 스테이지 재생, 전체 화면 캡처 등)는 사용자가 명시적으로 요청했을 때만 한다. "고쳐줘", "계속해줘", "빌드해줘", "확인해줘"는 전체 검사의 허락이 아니다.
- 작은 검사를 여러 번 이어 붙여 요청받지 않은 전체 검사로 만들지 않는다.
- 검사를 고르기 전에 그 검사가 실제로 무엇을 돌리는지 확인한다. 전체 검사가 묶여 있으면 필요한 부분만 도는 경로를 쓴다.

## 실행

- `project.yaml`에 적힌 검증 실행 방법을 쓴다. 이미 있는 검사를 다시 쓰고, 필요한 범위만 고른다.
- 결과는 요약부터 읽는다. 요약의 실행 번호, 범위, 완료 상태가 방금 돌린 것과 맞는지 확인한다.
- 자세한 기록과 저장된 화면은 실패한 검사나 바뀐 화면을 눈으로 확인해야 할 때만 연다. 성공한 결과물을 전부 열어 보지 않는다.
- 시간 초과나 중단이 생기면 다시 돌리기 전에 대기 중이거나 실행 중인 작업이 남아 있는지 확인한다. 아직 돌고 있을 수 있다.

## 보고

- 자동 검사와 실제로 눈으로 본 검토를 따로 보고한다. 화면을 저장한 것만으로는 눈으로 확인한 것이 아니다.
- 실제로 돌린 범위를 말한다. 검사 작업 수로 스테이지 수를 짐작하지 않는다.
- 돌리지 않은 검사를 통과했다고 하지 않는다.
- 예전 결과물을 방금 돌린 결과의 근거로 쓰지 않는다.
