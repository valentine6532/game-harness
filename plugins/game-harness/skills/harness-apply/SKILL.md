# 하네스 적용

플러그인에 들어 있는 하네스 내용물을 게임 프로젝트의 `.game-harness/harness/`로 복사하고, 입구 파일과 설정을 만든다.

## 도구 위치

관리 도구는 `${CLAUDE_PLUGIN_ROOT}/scripts/harness.py`다. 이 경로에 `${...}`가 글자 그대로 남아 있으면, 이 `SKILL.md`가 있는 폴더에서 `../../scripts/harness.py`를 찾아 쓴다.

## 절차

### 1. 현재 상태를 확인한다

게임 프로젝트의 최상위 폴더에서 실행한다.

```
python "<도구 경로>" status --project .
```

- 이미 적용되어 있다고 나오면 다시 적용하지 않는다. 상태를 알리고, 새 버전을 원하면 `harness-update`를 쓴다고 안내한다.
- 적용되어 있지 않으면 선택 가능한 기능 목록이 나온다.

### 2. 프로젝트를 조사한다

새 폴더인지 기존 게임인지 확인한다. 기존 게임이면 다음을 조사한다.

- 엔진과 버전, 엔진 프로젝트 폴더
- 폴더 구조: 실제 작업 대상, 참고용 폴더, 데이터 원본, 생성되는 파일
- 기존 `AGENTS.md`, `CLAUDE.md`의 규칙
- 검증 도구와 실행 방법, 검증 요약 파일 위치
- git 저장소인지

이 단계에서는 아무것도 바꾸지 않는다. 문서 전체를 훑지 말고 입구 파일과 최상위 구조에서 알 수 있는 만큼만 본다.

### 3. 기능을 고른다

조사 결과에 맞는 기능을 선택 가능한 목록에서 고른다. 예를 들어 Unity 프로젝트면 `unity`다. 맞는 기능이 없으면 공통 절차만 적용한다. 고른 기능과 이유를 사용자에게 알린다.

프로젝트가 git 저장소가 아니면, 하네스 업데이트를 되돌리려면 git이 필요하다는 점을 알리고 `git init`을 할지 묻는다.

### 4. 적용한다

```
python "<도구 경로>" apply --project . --modules unity
```

기능이 없으면 `--modules`를 뺀다. 이 명령이 하는 일:

- `.game-harness/harness/`에 내용물 복사
- `.game-harness/manifest.json` 기록
- `.game-harness/project.yaml`, `.game-harness/overrides/README.md` 생성(없을 때만)
- `AGENTS.md`에 하네스 구역 추가. 기존 내용은 그대로 두고 맨 아래에 덧붙인다
- `CLAUDE.md` 생성(없을 때만)

### 5. 설정을 채운다

`.game-harness/project.yaml`의 빈 항목을 2단계에서 조사한 내용으로 채운다. 확인하지 못한 항목은 추측으로 채우지 말고 비워 둔다.

기존 `AGENTS.md`에 "요청 없이는 하지 않는 작업"에 해당하는 규칙(빌드 제한, 전체 검사 제한 등)이 있으면 `requires_explicit_request`에 옮겨 적는다. 기존 `AGENTS.md`의 내용은 지우거나 고쳐 쓰지 않는다.

출력의 "확인할 것"에 `CLAUDE.md`가 `AGENTS.md`를 불러오지 않는다고 나오면, 기존 `CLAUDE.md`에 `@AGENTS.md` 한 줄을 추가할지 사용자에게 묻는다.

### 6. 보고한다

- 적용한 버전과 기능
- 새로 만든 파일
- `project.yaml`에서 채운 항목과 비워 둔 항목
- 기존 `AGENTS.md`의 규칙 중 공통 절차와 겹치거나 충돌해 보이는 것. 정리는 사용자가 정할 일이므로 목록만 알린다.

커밋은 사용자가 요청했을 때 한다.

## 지킬 것

- 기존 프로젝트 파일을 지우거나 초기화하지 않는다.
- `.game-harness/harness/` 안의 파일과 `manifest.json`을 직접 만들거나 고치지 않는다. 항상 도구를 쓴다.
- 게임의 기획 문서나 코드를 하네스에 맞추겠다고 옮기거나 고치지 않는다.
