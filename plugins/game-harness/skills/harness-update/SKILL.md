# 하네스 업데이트

`.game-harness/harness/`를 플러그인에 들어 있는 버전으로 통째로 바꾼다. `project.yaml`, `overrides/`, `AGENTS.md`의 하네스 구역 밖, `docs/`는 바꾸지 않는다.

전역 제작 스킬·에이전트는 플러그인 갱신 뒤 다음 세션의 훅이 자동 동기화한다. 이 프로젝트의 하네스 절차 업데이트와 별개다. 전역 상태는 `harness.py global-status`, 동기화는 `global-sync`, 같은 버전의 복구는 `global-repair`로 확인·처리한다. 전역 설치본은 직접 고치지 않으며, 프로젝트의 `overrides/skills/`와 `overrides/agents/`는 두 업데이트 모두에서 보존한다.

## 도구 위치

관리 도구는 `${CLAUDE_PLUGIN_ROOT}/scripts/harness.py`다. 이 경로에 `${...}`가 글자 그대로 남아 있으면, 이 `SKILL.md`가 있는 폴더에서 `../../scripts/harness.py`를 찾아 쓴다.

## 절차

### 1. 차이를 확인한다

게임 프로젝트의 최상위 폴더에서 실행한다. 이 명령은 아무것도 바꾸지 않는다.

```
python "<도구 경로>" diff --project .
```

기능을 추가하거나 빼려는 요청이면 원하는 전체 기능 목록을 `--modules unity,...`로 준다.

"차이 없음"이면 `status`를 실행해 GitHub에 더 새 버전이 올라와 있는지 확인한다.

- 없으면 이미 최신이라고 알리고 끝낸다.
- "GitHub에 새 버전이 올라와 있다"고 나오면, 이 PC에 설치된 플러그인이 아직 예전 버전이라 적용할 수 없는 상태다. 그렇게 알리고 `harness-status`의 5번에 적힌 플러그인 갱신 방법을 안내한다. 갱신한 뒤 새 세션에서 다시 요청하면 된다.

### 2. 차이를 보여주고 진행할지 묻는다

차이가 있으면 **반드시** 다음을 사용자에게 보여주고, 업데이트를 진행할지 묻는다. 요청에 "업데이트해줘"라고 적혀 있었더라도 이 확인을 건너뛰지 않는다.

- 현재 버전과 새 버전
- 변경 내용(출력의 `[버전 변경 내용]`)
- 추가·삭제·내용이 바뀌는 파일
- 손으로 고쳐진 파일: 업데이트하면 덮어써져 사라진다. 이 항목이 있으면 각 파일에서 무엇이 고쳐졌는지 확인해 알려주고, 남겨야 할 내용은 먼저 `.game-harness/overrides/`로 옮길지 묻는다.
- 경고

사용자가 진행하지 않겠다고 하면 아무것도 바꾸지 않고 끝낸다.

### 3. 되돌릴 수 있는 상태로 만든다

- 프로젝트가 git 저장소가 아니라는 경고가 있으면, 업데이트를 되돌릴 방법이 없다는 점을 알리고 그래도 진행할지 확인한다.
- 커밋되지 않은 변경이 있다는 경고가 있으면, 먼저 커밋할지 사용자에게 묻는다. 사용자의 작업을 임의로 커밋하거나 버리지 않는다.

### 4. 적용한다

사용자가 진행하겠다고 답한 뒤에만 `--yes`를 붙여 실행한다. 1단계에서 `--modules`를 썼다면 똑같이 준다.

```
python "<도구 경로>" update --project . --yes
```

### 5. 확인하고 커밋한다

1. `python "<도구 경로>" status --project .`로 차이가 없어졌는지 확인한다.
2. 새 버전의 변경 내용이 이 게임의 `overrides/`나 `AGENTS.md` 규칙과 충돌하거나 겹치는지 읽어 본다. 공통 버전에 반영되어 필요 없어진 임시 규칙이 있으면 지울지 사용자에게 묻는다.
3. `.game-harness/project.yaml`에 적힌 검증 중 이번 변경과 관련된 것을 실행한다.
4. 문제가 없으면 하네스 업데이트만 담은 커밋을 하나 만든다. 커밋 메시지에 이전 버전과 새 버전을 적는다. 이 커밋이 복구의 기준이 된다.
5. 문제가 있으면 원인을 사용자에게 알리고, 되돌릴지 묻는다. 되돌리기는 `harness-rollback`을 따른다.

## 지킬 것

- 확인 없이 `--yes`를 붙이지 않는다.
- `.game-harness/harness/` 안의 파일을 직접 고쳐서 "업데이트"하지 않는다. 항상 도구를 쓴다.
- `manifest.json`을 직접 고치지 않는다.
