# 공통 하네스에 반영

공통 하네스의 원본 저장소에 있는 `plugins/game-harness/payload/`를 고치고, 시험하고, 새 버전을 만든다. 게임 프로젝트의 `.game-harness/harness/`나 설치된 플러그인 캐시를 직접 고치지 않는다.

## 도구 위치

관리 도구는 `${CLAUDE_PLUGIN_ROOT}/scripts/harness.py`다. 이 경로에 `${...}`가 글자 그대로 남아 있으면, 이 `SKILL.md`가 있는 폴더에서 `../../scripts/harness.py`를 찾아 쓴다.

## 절차

### 1. 공통으로 올릴 일인지 판단한다

- 이 게임에만 해당하는 일이면 공통 하네스를 고치지 않는다. 게임의 `.game-harness/project.yaml`이나 `.game-harness/overrides/`에 적는다.
- 다른 게임에서도 생길 문제이거나 여러 게임에 필요한 절차면 공통으로 올린다.
- 판단이 서지 않으면 사용자에게 묻는다. 한 게임의 요구를 모든 게임의 규칙으로 성급하게 바꾸지 않는다.

### 2. 문제를 정리한다

무엇이 문제였는지, 어떤 조건에서 생기는지, 지금 절차의 어느 부분이 그것을 막지 못했는지 정리한다.

### 3. 원본 저장소를 찾는다

```
python "<도구 경로>" source
```

경로가 나오면 그곳이 원본 저장소다. 설치된 사본이라고 나오면, 원본 저장소(`https://github.com/valentine6532/game-harness`)를 받아 둔 폴더가 이 PC에 있는지 사용자에게 묻는다. 설치된 사본 안의 파일은 고치지 않는다.

- 원본 저장소가 있고 사용자가 직접 고칠 수 있으면 4단계로 간다.
- 원본 저장소가 없거나 고칠 권한이 없으면, 2단계에서 정리한 문제와 제안하는 수정 내용을 원본 저장소에 올릴 개선 제안(이슈) 글로 작성해 사용자에게 보여준다. 사용자가 확인하면 올리고, 당장은 게임의 `.game-harness/overrides/`에 임시 규칙을 적는다. 여기서 끝낸다.

원본 저장소에 커밋되지 않은 변경이 있으면 사용자에게 알리고 어떻게 할지 묻는다.

### 4. 내용물을 고친다

원본 저장소의 `plugins/game-harness/payload/`에서 고친다.

- 모든 게임에 해당하면 `core/`
- 특정 엔진이나 플랫폼에만 해당하면 `modules/<이름>/`
- 게임 이름, 그 게임의 경로, 그 게임의 규칙을 적지 않는다. 게임마다 달라지는 값은 `project.yaml`을 읽도록 쓴다.

### 5. 버전을 올린다

세 곳을 함께 고친다.

- `plugins/game-harness/plugin.json`의 `version`
- `plugins/game-harness/.claude-plugin/plugin.json`의 `version`
- `plugins/game-harness/payload/CHANGELOG.md` 맨 위에 `## <버전> - <날짜>` 항목. 무엇을 왜 바꿨는지, 게임 쪽에서 따로 해야 할 일이 있으면 그것도 적는다.

제목 형식은 업데이트할 때 변경 내용을 뽑는 기준이므로 그대로 지킨다.

### 6. 시험한다

원본 저장소에서 실행한다.

```
python plugins/game-harness/scripts/harness.py check
python -m unittest discover -s tests
```

둘 다 통과해야 한다. `harness.py`의 동작을 바꿨다면 `tests/test_harness.py`에 시험을 추가한다.

### 7. 커밋한다

변경 내용을 사용자에게 보여주고 확인을 받은 뒤 커밋한다.

태그는 수정할 때마다 붙이지 않는다. 여러 수정을 커밋으로 쌓아 두었다가, 사용자가 GitHub에 올리라고 했을 때 `v<버전>` 태그를 붙여 커밋과 함께 올린다(`git push`와 태그 푸시). 사용자가 올리라고 하기 전에는 태그도 푸시도 하지 않는다.

아직 태그를 붙이지 않은 버전에 수정을 더할 때는 버전 번호를 다시 올리지 않고, `CHANGELOG.md`의 같은 버전 항목에 내용을 덧붙인다.

### 8. 다음 단계를 안내한다

- 설치된 플러그인 갱신: 원본 저장소를 로컬 폴더로 등록해 쓰는 경우 Claude Code는 `/reload-plugins`나 새 세션, Codex는 앱 재시작. GitHub에서 설치한 사용자는 새 버전이 올라간 뒤 플러그인 갱신을 실행해야 받는다.
- 각 게임에 적용하려면 그 게임 폴더에서 `harness-update`를 요청한다. 다른 게임은 요청하기 전까지 기존 버전 그대로다.
- 게임의 `overrides/`에 이 문제를 피하려고 적어 둔 임시 규칙이 있으면, 업데이트한 뒤 지운다.

## 지킬 것

- 게임 프로젝트의 `.game-harness/harness/`를 고치지 않는다.
- 설치된 플러그인 캐시를 고치지 않는다.
- 시험을 통과하지 못한 상태로 태그를 붙이지 않는다.
- 다른 게임 프로젝트를 임의로 업데이트하지 않는다.
