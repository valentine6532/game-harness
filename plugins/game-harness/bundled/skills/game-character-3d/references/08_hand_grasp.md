# 기존 캐릭터의 손을 실제 칼자루에 맞추기

손가락이 자루를 감싸지 않거나, 고정 주먹이 팔에 꽂힌 무기처럼 보일 때 읽는다. 08 방식 B1의 **쥔 자세로 바인드한 손 교체**를 데스나이트 오른손에서 검증했다(2026-09-30). 기존 엔진 뼈·클립을 보존하고 손가락 뼈 15개를 추가했다. 사용자는 파지는 승인했지만 휘두르기는 여전히 막대를 내리치는 느낌이라고 평가했다. 파지·장착·검 동작을 각각 판정한다.

## 1. 실제 엔진 기준 자세 확보

- 설치된 메시와 실제 무기, 기존 뼈의 기준 변환, 무기 상대 변환을 읽거나 내보낸다. 원본 FBX를 Blender로 가져온 기준 자세와 엔진의 실제 기준 손 회전·축·스케일이 같다고 가정하지 않는다.
- 손 크기, 칼자루 단면·중심선·사용 가능한 길이를 잰다. 검사 원통은 초기 굽힘 시험에 사용할 수 있지만 그 반지름·위치를 최종 소켓에 복사하지 않는다.
- 기존 뼈 이름·계층·기준 변환을 저장한다. 손 교체 후 수치 비교로 보존 여부를 확인하고 동작을 재생한다. 원래 뼈를 변경한 경우에는 기존 클립을 그대로 사용할 수 있다고 단정하지 않는다.
- 쥔 동작에서 손바닥과 칼자루의 관계를 정한 뒤, 실제 엔진 기준 자세와 손 소켓 공간으로 환산해 부착 변환을 저장한다. 대기 애니메이션이 재생 중인 손 좌표를 기준 자세 좌표처럼 쓰지 않는다.

## 2. 후보 손 형상과 가중치

- 자동 관절 검출 전에 다섯 손가락과 손바닥의 가지 연결을 검사한다. 생성된 여분 가지를 손가락으로 오인하면 실제 손가락과 관절·가중치가 어긋난다. 이번 후보에는 손바닥의 여분 손가락 가지가 있었다.
- 원형 손을 사용할 수 있으면 재생성보다 먼저 검토한다. 부적합한 손을 또 생성할 때는 02의 비용·승인 범위를 따른다.
- 자동 검출/전이 가중치가 실패하면 실제 마디를 수동 배치하고 손가락 앞뒤 표면이 같은 마디에 묶였는지 확인한다. 다른 손에 관절 좌표를 복사하지 않는다.
- 손 주변 허벅지·골반 등에서 잘못 전이된 가중치를 제거한다. 손바닥·손목은 손/전완에, 손가락은 각 마디에 연결하고 정규화한다. 팔 커프 아래 접합도 검사한다.
- 실제 칼자루 둘레에 네 손가락을 굽히고 엄지가 반대쪽을 받치게 한다. 손목을 과하게 틀거나 무기를 손 안에서 미끄러뜨려 접촉을 맞추지 않는다. 자루 내부로 들어가는 표면·손끝 틈·장갑 안쪽을 확대 검사한다.
- 메시 좌표를 직접 변형한 뒤 원래 커스텀 법선을 유지하면 표면 음영이 틀릴 수 있다. 형상에 맞는 법선·탄젠트를 갱신한다.
- 열린 경계를 메우기 전에 UV/법선 분리로 생긴 중복 정점과 실제 구멍을 구분한다. 필요한 경계만 용접하고 UV·가중치를 확인한 뒤 구멍을 막는다. 중복 경계를 모두 채우면 불필요한 면이 생긴다.

## 3. 고정 파지와 움직이는 손가락 선택

- 무기 하나를 계속 잡는 범위에서는 닫힌 손을 새 손가락의 바인드 자세로 사용할 수 있다. 손가락 트랙 없는 기존 클립은 이 자세를 사용하므로 기존 몸 동작을 재생할 수 있다. 손가락 키가 있는 클립이나 이전 자세가 남는 런타임이 섞이면 실제 전환을 확인하고 필요한 기본값 채널을 추가한다.
- 고정 파지는 열기·잡기·놓기 애니메이션을 구현한 결과가 아니다. 무기 굵기 변경·다른 파지·칼집 넣기에는 추가 자세나 손가락 트랙이 필요하다. Mixamo 손가락 회전 리타깃 경로는 08에 남긴 별도 미검증 선택지다.
- 기존 손 뼈 아래 새 손가락 뼈를 추가한다. 기존 엔진 기준 뼈를 보존했다면 같은 스켈레톤과 기존 몸 클립을 재사용하는 임포트를 우선 검토한다. 손가락을 추가했다는 이유만으로 몸 전체를 다시 리깅하거나 캐릭터 폴더를 삭제하지 않는다.
- 무기 이동·회전이 바뀌면 부착 변환과 새 손을 함께 저장한다. 날 방향·적중 위치·몸 관통도 다시 검사한다. 이번 모델의 15개 뼈·칼 이동 약 5.20cm·천 섹션 번호는 재사용 기본값이 아니다.

## 4. 엔진 설치와 실제 자세 검사

- 새 손 재질 슬롯이 추가되면 기존 몸 재질·물리·천 섹션 번호를 확인한다. 보이는 천과 시뮬레이션 복사본 연결을 새 번호에 맞추고 별도 망토의 리더 포즈도 검사한다.
- 같은 카메라·같은 샘플의 전후를 실제 게임/PIE에서 촬영한다. 에디터에서 애니메이션 시간을 설정한 것만으로 실제 자세가 평가되었다고 믿지 않는다. 자세별 손 뼈 좌표와 애니메이션 위치가 변하는지 확인한다.
- 대기·달리기·준비·적중·통과·회수에서 손가락 접촉과 손목 접합을 검사한다. 적·망토·이펙트가 가리면 검사 세션에서 잠시 숨긴다. 정지 검사에서 피격 섬광이 남는 경우도 정리하고, 검사 세션 종료 후 게임 설정을 복구한다.
- 기존 기준 자세·클립 참조 보존과 명중 로그는 각각 구조·판정의 근거다. 파지는 확대 전후로, 검 동작 품질은 정상 게임 카메라·정상 속도로 별도 확인한다.
- 에디터와 게임을 동시에 실행해 VRAM 경고가 겹치면 저장 후 동시 실행을 줄여 촬영한다. 프로세스 종료는 사용자에게 허용받은 범위를 따른다.
- 맵·에셋·기준 변환·재적용 방법을 저장한다. 별도 설치를 전체 생성기가 덮어쓰는지 확인하고 미통합 상태라면 기록한다. 몸/스켈레톤을 재생성하면 이전 손 교체본이 새 기준 자세에도 맞는지부터 확인한다.

## 5. 쥔 모양은 좋지만 막대를 휘두르는 느낌일 때

### 먼저 할 것: 모션캡처 팔을 지킨다 (2026-09-30 해결, 사용자 확인)

데스나이트는 이 증상으로 여러 차례 팔을 다시 설계했지만(아래 "후속 보정"~"전체 재설계" 사례) 모두 거절됐다. **원인은 팔·손목을 몸과 따로 각도 목표로 다시 만든 것 자체였다.** 모션캡처에는 손(팔꿈치)이 먼저 나가는 동안 손목이 꺾여 칼이 뒤에 남고, 마지막에 손목이 풀려 칼끝이 튀어 나가는 채찍 흐름이 있다. 프레임마다 칼 방향을 목표에 맞추면 이 시간차가 사라지고 칼이 팔뚝과 한 덩어리로 돈다. 원본 팔로 되돌리자 사용자가 "좋다"고 확인했다.

1. **원본과 현재의 손·칼끝 시간차를 잰다.** `scripts/swing_lag.py -- <fbx> <out.json> [클립]`은 타마다 손 속도 최고점과 칼끝 속도 최고점의 프레임 차(`lag`), 최고점의 칼끝/손 속도비(`tip_over_hand`), 어깨·골반 비틀기, 엉덩이 낮춤, 몸통 기울기를 낸다. Mixamo 원본은 검지-새끼 관절선을 칼 방향으로 쓰고, 주인공은 스크립트의 장착 칼 축 값을 대상 캐릭터 값으로 바꿔 쓴다. 데스나이트 1타는 팔 재작성본이 지연0·속도비2.0, 원본 팔이 지연3프레임·3.6이었다. 지연이 0이고 속도비가 낮으면 막대다. 단, 게임 렌더 프레임으로 잰 지연은 재생 배속이 오르면 샘플링 때문에 줄어든다. 배속을 바꾼 비교에서는 속도비로 판단한다(07 "무기 성격에 맞는 리듬").
2. **팔은 원본 모션캡처를 쓴다.** 몸 과장(`--rezero`, `--exaggerate`, `exaggerate_attack.py`의 보폭·낮추기·몸통 선행)은 엉덩이·척추·머리·다리만 건드리므로 유지한다. 팔·손목 트랙에 각도 목표·IK·경로 설계를 덮어쓰지 않는다.
3. **날 방향은 일정한 손 회전 하나로 맞춘다.** 원본 팔에서 넓은 면이 앞서면, 대개 원본 무기와 우리 무기의 쥐는 방향 차이(데스나이트 약 45°)다. `scripts/edge_roll_scan.py -- <fbx> <클립> f0-f1 ...`로 칼 축 둘레 -90~90° 손 회전마다 속도 가중 면 기울기(`edge_tilt.py`와 같은 정의)를 재서 최소 각도를 찾는다. 타마다 최소 각도가 비슷하면 쥐는 방향 차이이므로 한 값을 쓴다. `process_character.py --attack-sword-axis x:y:z --attack-edge-roll clip=DEG`가 해당 클립의 모든 손 회전 키에 곱한다. 데스나이트는 onehand·power 모두 -40°, 면 기울기 40/33/35°→10/17/10°였다. 대기·달리기는 바꾸지 않는다. 두 스크립트의 칼 축·날 폭 축 값도 대상 캐릭터의 실제 장착 값으로 바꾼다.
4. **같은 조건으로 전후를 본다.** 효과 없는 Blender 비교(칼은 장착 축의 판으로 대신)와 실제 게임(망토·잔상 끔, 전신이 보이는 카메라)을 나란히 본다. 게임 연속 촬영 파일 이름은 앞자리0이 없으니 숫자로 정렬한다.
5. 그래도 상체가 꼿꼿해 보이면 팔이 아니라 몸 과장 값을 키운다. 쾌검은 낮추기·숙이기보다 비틀기(`--exaggerate`, `--attack-drive-scale`)를 키운다. 베기 배속을 낮춰 느리게 만들면 막대 느낌은 줄어도 "자연스럽지만 맛이 없다"가 된다(2026-10-01). 뼈 데이터는 그다음에 건드린다.

아래 사례들은 **이 방법 이전의 실패 기록**이다. 같은 증상에 팔 재작성을 다시 시도하지 않는다. 경계 프레임·양날 분기·재생 끝 연장·PIE 촬영 같은 개별 주의점만 참고한다.

파지 작업과 후속 동작 보정을 구분한다. 2026-09-30 후속 엔진 측정에서는 적중 직후 각도 급변, 베기 중 수직 자세, 실제 날 방향을 보정했으나 사용자는 여전히 막대처럼 느껴진다고 평가했다. 이후 준비 때 칼과 전완이 거의 일직선인 관계를 측정하고 팔 경로를 다시 보정했다. 최신 동작도 사용자 만족을 확인받은 것으로 기록하지 않는다.

- 손 위치·팔꿈치·전완/손목 회전·칼끝 경로·날의 선행 방향을 시간에 따라 함께 본다. 준비 자세의 기울기를 맞추는 것만으로 전체 베기가 자연스러워지는 것은 아니다.
- 골반·가슴·어깨/팔·손목/칼끝의 가속 시점과 통과 후 감속·회수를 검사한다. 모두 함께 움직이는 느낌과 손목에 회전이 몰리는 느낌을 구분한다. 무기가 손 뼈에 붙는 것은 정상적인 부착 방식이며 부착 자체를 원인으로 단정하지 않는다.
- 실제 타격 구간 시간은 `원본 프레임 간격 / 원본 Hz / 재생 배속`으로 계산한다. 7프레임/30Hz/2.1배속은 약 0.111초다. 빠르다는 사실만으로 오류라고 판단하지 말고 정상 속도에서 준비·가속·통과가 읽히는지 확인한다.
- 적중 뒤 유지와 다음 타로의 전환이 베기를 끊는지 확인한다. 검술의 통과 동작에 07의 급정지·버팀을 일률적으로 강화하지 않는다.
- 효과를 끈 동작 검사와 최종 게임 화면을 함께 사용한다. 명중률과 날 방향 수치만으로 사용자 동작 불만까지 해결됐다고 보고하지 않는다.

### 후속 보정에서 확인한 재사용 지침

- 준비·적중·통과를 각각 맞춘 뒤 경계 프레임의 방향과 회전 속도를 검사한다. 한 구간 끝에서 원본 자세를 복원하면 다음 프레임에 큰 꺾임이 생길 수 있다. 이 사례는 1타 적중 직후 칼 높이 각도가 31.6° 변했다. 적중을 지나 속도가 이어지는 곡선으로 연결해 4.6°로 줄였다. 모든 키에 smoothstep을 따로 쓰면 각 키에서 속도가 0이 되므로 베기 연결에 일률 적용하지 않는다.
- 실제 장착 변환으로 **날의 길이 축과 폭 축을 모두 측정**한다. FBX 주먹 구멍의 축에 맞춘 과거 날 정렬은 현재 엔진 부착을 검증한 값이 아니다. 실제 칼끝 속도를 날의 폭 방향/두께 방향에 투영해 면이 앞서는 구간을 찾는다. 이 사례는 게임 로그의 칼끝 로컬 좌표·실제 장착 변환과 원본 프레임 간격으로 비교했으며, 평균 면 방향 기울기 약 32~57°→2~3°였다. 실제 접촉 판정이나 최종 사용자 만족을 증명한 값은 아니다.
- 칼을 손 안에서 돌리지 말고 손·전완 트랙을 회전시켜 날 방향을 맞춘다. 진행 방향에서 길이 축 성분을 제거한 접선에 날 폭 방향을 맞추고, 동등한 두 날 방향 중 시간적으로 가까운 방향을 택한다. 전완 축 회전과 손목 회전에 분산하며 손 위치·팔꿈치·파지를 재검사한다. 급격한 방향 변화나 정지 구간에는 목표를 완화한다.
- 후속 사례는 일반 3타의 공격자 유지 0.04초를 제거하고 통과를 원본 3→5프레임으로 늘렸다. 적의 피격 정지와 충격파의 별도 유지 동작은 보존했다. 이 수치는 다른 게임의 기본값이 아니다.
- Unreal의 뼈 이름은 대소문자를 구분하지 않는 FName이다. 재가져오기 후 표시 대소문자가 달라져도 뼈 추가/삭제로 오인하지 말고, 이름을 정규화해 비교한 뒤 실제 계층·기준 변환을 검사한다.

### 팔꿈치·손의 경로를 다시 보정한 사례

- 칼끝 방향이 좋아도 팔과 칼이 한 줄로 이어지면 팔에 붙은 막대처럼 읽힐 수 있다. 실제 엔진의 전완→손 벡터와 장착된 칼 길이 축의 각도를 준비부터 통과까지 함께 검사한다. 이 사례의 준비 각도는 약17~24°였다. 각도만으로 원인을 확정하거나 모든 무기에 동일한 목표를 적용하지 않는다.
- 팔꿈치 위치와 손의 경로를 함께 설계한다. 이 사례는 팔꿈치를 앞·아래로 접고, 손이 먼저 나간 뒤 손목이 풀리게 했다. 준비/베기 시작/적중에서 전완과 칼의 각도는 약70/80/30°로 바뀌었다. 실제 전후 자세에서 변화를 확인한 측정값이며 검술 품질의 보편적인 합격 각도가 아니다. 이미 맞춘 손 안의 칼을 돌려서 해결하지 않는다.
- 손목 회전을 최소화하는 IK 폴 선택은 전완과 칼을 정렬시킬 수 있다. 프레임마다 반대 폴을 선택하면 팔꿈치와 손목이 갑자기 뒤집힌다. 연속적인 팔꿈치 경로·같은 폴 분기 또는 직접 관절 회전을 사용하고, 위치·회전의 프레임 간 변화와 실제 관절 접합을 검사한다.
- PIE 시작 직후 캡처하면 게임 대신 에디터 화면이 저장될 수 있다. 뷰포트가 안정된 뒤 촬영하고 결과를 직접 열어 확인한다. 효과를 끈 엔진 자세를 게임 배속으로 재생한 영상과 실제 런타임 전투 영상을 구분해 표기한다.
- 저장된 Blender 장면에서 빠르게 동작만 다시 내보내면 Root 채널이 달라질 수 있다. 원본 기준 뼈뿐 아니라 설치된 애니메이션의 Root·몸·발도 비교하고, 팔만 바꾸는 작업에서는 기존 루트 채널을 보존한다. 최종 소스·설치 스크립트·엔진 결과를 함께 기록한다.

이번 방식은 전용 모델·수동 관절/가중치로 검증했다. 스킬의 기존 자동 도구가 이 손 교체 공정을 구현한다고 가정하지 말고 대상 모델에 맞게 작성·검사한다.

### 준비 자세부터 전체 공격을 다시 설계할 때

- 손을 올리는 것과 칼끝을 위로 세우는 것을 구분한다. 뒤로 넘긴 칼을 요청한 그림에는 손의 높이·칼끝의 전후 위치·팔꿈치 굽힘을 함께 맞춘다. 이전의 바깥 사선 요구를 계속 유지해서 최신 그림을 무시하지 않는다.
- 몸통의 빠른 비틀림을 그대로 칼 방향의 기준축으로 사용하면 칼도 함께 돌아가 막대처럼 읽힐 수 있다. 몸의 공격 방향·체중 이동으로 베기 평면을 정하고 손의 이동과 칼끝의 가속을 따로 설계한다. 내려베기·역베기·마무리와 회수·다음 타 연결까지 정상 속도로 검토한다.
- 프레임마다 원본 관절에서 목표 방향으로 최단 회전만 계산하면 축 회전이 불연속일 수 있다. 대상 뼈의 실제 자식 방향·기준 좌표계를 확보하고 연속적인 굽힘 평면과 폴을 사용한다. 관절 곡선을 부드럽게 만든 뒤에는 칼끝 경로·파지와 날 방향을 다시 검사한다.
- 양날 검은 날 방향 두 선택지가 기하학적으로 동등해도, 매 프레임 가까운 방향을 새로 선택하면 경계에서 손이180° 뒤집힐 수 있다. 시간에 따라 회전 분기를 이어서 준비부터 회수까지 검사한다. 적중 구간만 검사하면 회수의 뒤집힘을 놓친다.
- 회수 시간을 늘리기 위해 재생 끝만 연장하지 않는다. 원본 클립의 몸 위치 초기화·다음 공격 준비·몸 이동 재적용 경계를 확인한다. 데스나이트 시험은 끝 범위를 연장해 몸 이동 최대가 약19→102cm/프레임으로 튀었다. 원래 유효 구간 안에서 회수를 다시 설계하고 실제 전투로 재검증했다. 숫자는 이 프로젝트의 실패 기록이다.
- 캡처 시 뼈 좌표가 바뀌는 것과 요청한 엔진 자세가 실제 평가되는 것을 함께 확인한다. 자세 갱신·카메라 렌더를 기다리고, 확대 화면이 팔·갑옷 안쪽으로 들어가거나 머리 위 칼끝을 자르지 않는지 확인한다. 카메라가 다른 화면을 같은 구도 비교로 표기하지 않는다.
- 사용자가 전체 자연스러움 판단을 맡기면 특정 지적 한 개에만 한정하지 않는다. 준비의 긴장, 몸/손/칼의 순서, 날 선행, 관절 뒤집힘·관통, 발 지지, 감속·회수, 연속 공격과 실제 게임 속도를 스스로 확인하고 발견한 문제를 적용·재검증한다.
