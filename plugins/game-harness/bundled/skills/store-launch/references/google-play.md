# Google Play Console

Apple과 규칙이 다르다. 앱 코드는 대부분 공유되지만 콘솔 신고와 몇 가지 프로젝트 설정은 따로 해야 한다. 메뉴 이름과 수치는 작성 시점 기억 기준이므로 콘솔에서 확인한다.

## Apple과 다른 점

| 항목 | Apple | Google Play |
|---|---|---|
| 어린이 대상 표시 | Kids Category는 선택 | 타겟 연령대 신고는 필수이고 사실대로 |
| 어린이 대상일 때 광고 | Kids Category면 사실상 제한 | 가족용 인증 광고 SDK면 가능 (AdMob 해당) |
| 개인정보 신고 | 개인정보 라벨 | 데이터 보안 양식 (같은 내용을 다시 입력) |
| 출시 전 테스트 | TestFlight, 의무 기간 없음 | 새로 만든 개인 계정은 비공개 테스트(테스터 12명, 14일 연속)를 거쳐야 프로덕션 신청이 가능할 수 있음 |
| 계정 이메일 | Apple ID 변경이나 소유자 이전 가능 | 변경 불가. 사용자 추가나 다른 계정으로 앱 이전 |

비공개 테스트 요건은 기간이 걸리므로 계정 조건을 일찍 확인한다.

## 콘솔에서 할 일

| 위치 | 할 일 |
|---|---|
| 앱 콘텐츠 > 타겟층 및 콘텐츠 | 실제 대상 연령대. 13세 미만 포함 시 가족 정책 적용 |
| 앱 콘텐츠 > 데이터 보안 | 수집·공유 데이터 신고. `privacy.md`의 답안을 사용 |
| 앱 콘텐츠 > 광고 | 광고 포함 여부, 광고 ID 사용 여부 |
| 앱 콘텐츠 > 콘텐츠 등급 | 설문 |
| 앱 콘텐츠 > 개인정보처리방침 | 주소. 하나만 넣을 수 있음 |
| 스토어 등록정보 | 이름, 설명, 스크린샷, 그래픽 이미지(1024×500), 아이콘(512) |
| 수익 창출 > 인앱 상품 | 상품 생성과 활성화. ID는 앱 코드와 같게 |
| 결제 프로필 | 판매자 계정, 세금 정보 |
| 프로덕션 | 국가 선택, 출시 |

## 프로젝트에서 따로 챙길 것

- **광고 ID 권한**: 어린이 대상 앱은 광고 ID를 전송하면 안 된다. 광고 SDK가 `com.google.android.gms.permission.AD_ID` 권한을 자동으로 넣으므로 매니페스트에서 제거하는 설정이 있는지 확인한다. `scripts/inspect_build.py`로 AAB의 권한 목록을 본다.
- **분석의 광고 개인화 기본값**: iOS에서 Info.plist로 막았다면 Android 매니페스트에도 같은 설정이 필요하다.
- **테스트 스위치**: 테스트 광고와 테스트 결제가 플랫폼별로 따로인지, 공용인지 확인한다. 한 플랫폼만 먼저 출시하면 공용 스위치가 문제가 된다. `ads.md` 참고.
- **버전 코드**: 올릴 때마다 이전보다 커야 한다. 빌드 스크립트와 업로드 스크립트에 따로 적혀 있으면 함께 올린다.
- **서명**: 업로드 키가 이전 빌드와 같은지 확인한다.

## 계정을 새로 만들었을 때

기존 계정에 올려 둔 앱은 새 계정에서 같은 패키지명으로 다시 등록할 수 없다. Play Console의 앱 이전으로 옮겨야 패키지명, 인앱 상품, 서명 키가 유지된다. 이전이 끝나기 전에 옛 계정을 닫지 않는다. 이전 중에는 어느 계정으로 업로드할지 사용자와 정한다.

## 실기기 확인표

| 확인할 것 | 기대 결과 |
|---|---|
| 상품 화면 | 스토어 가격 표시. 내부 테스트 트랙으로 설치해야 결제가 동작 |
| 구매 | 라이선스 테스터 계정으로 테스트 결제 |
| 삭제 → 재설치 → 구매 복원 | 혜택이 돌아옴. Android는 기기 백업으로 저장 기록도 돌아올 수 있음 |
| 광고 | 재생과 보상 |
| 방침 링크, 언어 전환 | Apple과 같음 |
