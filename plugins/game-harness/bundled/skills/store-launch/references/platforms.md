# 공통으로 하는 일과 플랫폼별로 따로 하는 일

한 번 하면 두 스토어에 다 쓰이는 일과, 스토어마다 다시 해야 하는 일을 가른다. 한 플랫폼을 먼저 출시할 때 "이건 나중에 다른 쪽에서 또 해야 하나?"에 답하는 표다.

검증 수준: iOS 쪽은 실제 출시 준비를 끝까지 따라가며 확인한 내용이다. **Android 쪽은 내부 테스트 빌드까지만 해 보고 적은 것**이라, 프로덕션 출시를 진행하면서 틀린 곳을 고치고 빠진 것을 채운다. 맨 아래 "갱신 기록"에 날짜와 함께 남긴다.

## 한 번 하면 양쪽에 쓰이는 것

| 영역 | 일 | 메모 |
|---|---|---|
| 결정 | 앱 이름, 버전 번호, 수익 모델, 지원 언어, 출시 국가 | 버전 번호는 보통 양쪽이 공유 |
| 개인정보 | 앱이 수집·전송하는 정보 목록, 방침 작성과 게시, 지원 페이지 | 한 주소를 양쪽 콘솔에 넣음 |
| 앱 코드 | 앱 안의 방침 링크, 보호자 확인, 구매 복원 버튼, 결제 흐름 처리 | 같은 코드 |
| 광고 | 아동 대상·콘텐츠 등급 설정, 동의 화면, AdMob 계정과 지급 정보 | 계정은 하나 |
| 통계 | 이벤트 정의, 개인정보 미포함, 광고 개인화 차단(실행 중 설정), Firebase 프로젝트 | |
| 기록 | 체크리스트, 로그, 스토어 문구 초안의 대부분 | 설명·키워드는 스토어별로 길이 제한이 다름 |
| 사업 | 사업자등록, 통신판매업 신고 | `korea.md` |

## iOS에서만 하는 것

| 영역 | 일 |
|---|---|
| 계정 | Apple Developer Program, 유료 앱 계약·계좌·세금 |
| 결정 | Kids Category 등록 여부, iPad 지원 여부 |
| 프로젝트 | Info.plist 키(수출 규정, 분석 기본값), 추적 허용 요청을 쓰지 않는지, 서명과 배포 프로필 |
| 광고 | iOS용 앱 ID와 광고 단위 |
| 결제 | App Store Connect의 상품 등록과 심사용 스크린샷, 첫 버전에 상품 첨부 |
| 콘솔 | 버전 페이지, 앱 정보, 개인정보 라벨, 연령 등급, 가격 및 사용 가능 여부 |
| 테스트 | TestFlight (자동으로 시험 환경 결제) |
| 스크린샷 | iPhone 규격. 콘솔에 적힌 허용 크기 확인 |

세부: `apple.md`

## Android에서만 하는 것

| 영역 | 일 |
|---|---|
| 계정 | Google Play 개발자 계정(유형 확인), 결제 프로필 |
| 결정 | 타겟 연령대 (선택이 아니라 사실대로 신고) |
| 프로젝트 | 광고 ID 권한 제거, 매니페스트의 분석 기본값, 버전 코드, 업로드 키 서명, AAB 빌드 |
| 광고 | Android용 앱 ID와 광고 단위 |
| 결제 | Play Console의 상품 등록과 활성화, 라이선스 테스터 |
| 콘솔 | 타겟층 및 콘텐츠, 데이터 보안 양식, 콘텐츠 등급, 광고 신고, 스토어 등록정보 |
| 테스트 | 내부 테스트 트랙, 새 개인 계정이면 비공개 테스트 요건 |
| 스크린샷 | 휴대전화 스크린샷과 그래픽 이미지(1024×500) |

세부: `google-play.md`

## 양쪽에서 같은 일을 다른 방식으로 하는 것

| 일 | iOS | Android |
|---|---|---|
| 개인정보 신고 | 개인정보 라벨 (유형, 용도, 신원 연결, 추적) | 데이터 보안 양식 (수집, 공유, 용도) |
| 어린이 대상 처리 | Kids Category는 선택. 문구에서 "어린이용" 표현 제한 | 타겟 연령대 신고가 정책을 결정 |
| 광고 식별자 | 추적 허용을 요청하지 않으면 쓰지 않음 | 권한을 제거해야 쓰지 않음 |
| 테스트 광고 스위치 | 플랫폼별로 나눠 두면 한쪽만 먼저 실광고 가능 | 같음 |
| 결제 안내 문구 | "App Store" | "Google Play". 서로 섞이면 안 됨 |
| 저장 기록의 백업 | 기기 백업에 포함될 수 있음 | 자동 백업으로 재설치 때 돌아올 수 있음 |
| 빌드 번호 | 빌드마다 증가 | 버전 코드가 이전보다 커야 함 |

## 한 플랫폼을 먼저 낼 때

- 공용 설정(테스트 스위치, 버전 번호)을 바꾸면 다른 플랫폼의 테스트 빌드에 영향이 간다. 바꾸기 전에 플랫폼별로 나눌 수 있는지 본다.
- 방침과 지원 페이지는 양쪽 이용자가 함께 보므로 두 스토어를 모두 언급해도 된다. 앱 안과 스토어 문구에서는 그 스토어 이름만 쓴다.
- 뒤로 미룬 플랫폼의 일은 체크리스트에서 지우지 않고 "다른 쪽 출시 뒤에 진행"이라고 적어 둔다.
