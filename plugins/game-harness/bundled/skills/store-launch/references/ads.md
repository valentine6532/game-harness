# 광고 (AdMob)

## 용어부터

| 용어 | 뜻 | 모양 |
|---|---|---|
| 앱 ID | AdMob에 등록한 앱 하나. 플랫폼마다 따로 | `ca-app-pub-숫자~숫자` (가운데가 `~`) |
| 광고 단위 ID | 앱 안의 광고 자리 하나. 자리마다, 플랫폼마다 따로 | `ca-app-pub-숫자/숫자` (가운데가 `/`) |
| 테스트 광고 | Google이 주는 시험용 단위. 수익이 없고 안전함 | |

자리가 2개이고 플랫폼이 2개면 광고 단위는 4개가 필요하다. 사용자가 ID를 붙여 주면 `~`와 `/`가 맞는 자리에 들어갔는지, 게시자 번호가 앱 ID와 같은지 검사한다.

## 광고 단위 만들기 (사용자 안내)

1. https://apps.admob.com 로그인
2. **앱**에서 플랫폼에 맞는 앱 선택
3. **광고 단위 > 광고 단위 추가 > 형식 선택**(보상형 등)
4. 이름은 `ios-heart`, `android-region`처럼 플랫폼과 자리를 알 수 있게
5. 보상형의 보상 수량·항목은 앱이 그 값을 쓰는지에 따라. 쓰지 않으면 아무 값
6. **파트너 입찰**은 다른 회사의 광고 중개 서비스를 쓸 때만 체크. AdMob만 직접 쓰면 체크하지 않음
7. 만들면 나오는 ID를 복사

새 단위는 광고가 채워지기까지 몇 시간에서 하루쯤 걸릴 수 있다.

## 실광고로 전환할 때

- 테스트 스위치를 끄기 전에 그 플랫폼의 모든 자리에 ID가 있는지 확인한다. 빈 자리가 있으면 광고가 조용히 안 나온다. 이 조건을 검사 코드로 걸어 둔다.
- **스위치가 플랫폼 공용이면 나눈다.** 한 플랫폼만 먼저 출시할 때 공용 스위치는 다른 플랫폼의 테스트 빌드까지 실광고로 바꾼다.
- 에디터와 개발 빌드는 스위치와 상관없이 테스트 단위를 쓰게 한다.
- 스위치를 강제하던 기존 검사("테스트 광고여야 함")가 있으면 함께 고친다. 그렇지 않으면 스위치를 끈 순간 빌드나 검증이 실패한다.

## 어린이가 쓰는 앱

- 광고 요청에 아동 대상 표시와 콘텐츠 등급 제한(G)을 건다. 스토어의 어린이 코너 등록 여부와 무관하게, 실제 이용자가 어린이면 필요하다.
- iOS에서 추적 허용 요청(ATT)을 띄우지 않는다. 광고 식별자를 쓰지 않는다.
- Android에서 광고 ID 권한을 제거한다. `google-play.md` 참고.
- AdMob 콘솔의 앱 설정에서도 아동 대상으로 표시한다.
- 지역에 따라 동의 화면(UMP)이 필요하다. 동의를 다시 바꿀 수 있는 버튼을 보호자 메뉴에 둔다.

## 계정

- 같은 사람(같은 수취인)이 AdMob 계정을 여러 개 만들면 중복 계정으로 제한될 수 있다. 로그인 아이디를 바꾸고 싶으면 기존 계정의 설정 > 액세스 및 승인 > 사용자 관리에서 새 아이디를 관리자로 추가한다.
- 스토어 개발자 계정과 AdMob 계정은 다른 아이디여도 된다. 광고는 앱 ID로 연결된다.

## 자기 광고 주의

실광고가 나오는 빌드에서 개발자가 자기 광고를 반복해서 보거나 누르면 무효 트래픽으로 계정이 제한될 수 있다. AdMob의 설정 > 테스트 기기에 본인 기기를 등록하게 안내한다. TestFlight나 내부 테스트 빌드가 실광고로 바뀌는 시점에 반드시 알린다.

## 출시 후

- AdMob의 앱 설정에서 스토어 등록 정보와 연결한다. 출시 후에 가능하다.
- `app-ads.txt`를 스토어에 적은 개발자 웹사이트 루트에 올린다. 방침을 올린 사이트를 같이 쓸 수 있다.
